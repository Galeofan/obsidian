# **ЭТАП 0 — Формализация идеи (1–2 часа)**
Цель — превратить «хочу сайт о просмотренном контенте» в формулировку, понятную для разработки.
## 0.1. Ответить на три ключевых вопроса
1. **Что делает пользователь?**  
    «Добавляет фильмы/сериалы/видео, смотрит статистику, фильтрует.»
2. **Что именно я хочу показать миру?**  
    «Мой сервис отслеживания просмотренного контента.»
3. **Почему это интересно лично мне?**  
    Чтобы не бросить проект.
## 0.2. Сформировать формальный one-pager
Простой документ на 0.5 страницы:
- Цель
- Основные функции
- Ограничения (без авторизации? минимальные данные?)
- Что будет MVP, а что — будущее развитие

# **ЭТАП 1 — Планирование проекта как продукта (1 день)**
Цель — не писать код вслепую, а спроектировать то, что потом действительно будет работать.
## 1.1. Определить MVP
MVP = минимальная версия, которой можно пользоваться.
Пример:
- создать аккаунт или использовать фиксированного пользователя (MVP)
- добавить фильм/сериал/видео
- просмотреть список
- фильтрация по типу

Всё остальное — позже.
## 1.2. Определить “future features” (потом)
Например:
- рекомендации
- импорт с Кинопоиска/YouTube
- друзья/профили
- аналитика (сколько времени просмотрено)

Важно: **не внедрять их в MVP**.

# **ЭТАП 2 — Выбор технологий (2–4 часа)**
Цель — исключить спонтанные решения по ходу разработки.
## 2.1. Выбрать стек
- Frontend: **React + TypeScript + Vite**, UI-библиотека Material UI или Ant Design
- Backend: **Spring Boot 3.4**, Java 21, Gradle, JPA (или jOOQ в будущем)
- Database: **PostgreSQL**
- Deploy: Docker + docker-compose
- Документация API: Springdoc OpenAPI
## 2.2. Выбрать подход к архитектуре
На старте:
- backend: controller → service → repository
- frontend: feature-based structure + React Query (по желанию)

Позже можно модульную архитектуру.
## 2.3. Выбрать вспомогательные библиотеки
Backend:
- MapStruct (DTO → entity)
- Flyway (миграции)
- Lombok (по желанию)
- Logback (по дефолту)

Frontend:
- React Router
- Axios или Fetch
- Zustand / Redux Toolkit (если много состояния)
- React Hook Form (для форм)

# **ЭТАП 3 — Проектирование (реальное)**
## 3.1. Моделирование пользователя → сценариев → API → БД
Порядок такой:
### Шаг 1 — Use cases (пользовательские сценарии)
Список коротких предложений:
- Пользователь добавляет просмотренный фильм.
- Пользователь просматривает список.
- Пользователь удаляет элемент.
- Пользователь фильтрует по типу.
### Шаг 2 — Нарисовать UI-мокапы (очень важно!)
Используй Miro, Figma или даже бумагу.
Минимум:
- экран списка контента
- модалка «добавить элемент»

Мокапы помогают сформировать API.
### Шаг 3 — Определить REST API
Например:
```
POST   /api/content         # добавить просмотренный контент
GET    /api/content         # получить список (с фильтрами)
GET    /api/content/{id}    # получить один элемент
DELETE /api/content/{id}    # удалить
```
### Шаг 4 — Определить доменную модель / сущности
Например:
```
ContentItem:
    id: UUID
    userId: UUID
    type: MOVIE | SERIES | VIDEO
    title: string
    description: string (опционально)
    createdAt: timestamp
```
### Шаг 5 — Спроектировать схемы
Минимальные документы:
- **Entity Diagram (ER-диаграмма)**
- **API schema (OpenAPI)**
- **Diagram of flows** (как фронт вызывает бэкенд)
