# 🔥 Проблема, которую решают `inline` и `reified`
В обычном Kotlin-функции **параметр типа T стирается (type erasure)**.  
То есть внутри функции **нельзя узнать тип T**, потому что после компиляции он исчезает.

## Inline
Функция помеченная `inline` **не вызывается как обычный метод**, а **подставляется компилятором внутрь места вызова**.
Это важно, потому что, если функция _встраивается_ в место вызова, то компилятор **видит конкретный тип параметра**, и стирание типов перестает быть проблемой.
## reified
`reified` разрешает использовать **конкретный тип T внутри функции**.

### Пример
```
inline fun <reified T> isString(value: Any): Boolean {
    return value is T
}
```

inline позволяет использовать reified T, а именно — компилятор подставляет конкретный тип (String) внутрь тела функции при каждом вызове.
Без inline такой код не скомпилируется, потому что JVM стирает generic-типы.

🔥 Разбор построчно — что делает inline
1️. Команда компилятору: "Вставить тело функции прямо в место вызова"
Вызов:
```
isString<String>("hello")
```
после компиляции превращается примерно в:
```
"hello" is String
```
То есть никакой функции уже нет — её код приклеивается в место вызова.
Это называется inlining.
